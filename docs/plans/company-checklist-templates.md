# Company-built custom checklist templates — implementation plan

## Discovery

- The app is a vanilla JavaScript SPA: `public/live.js` renders template strings and dispatches `data-action` events; `public/live.css` and the existing refresh/company styles provide presentation.
- The server is a Node HTTP application in `server.mjs`, with role checks, company/property scoping, JSON-backed inspection answers, migrations under `migrations/`, and the existing `/api/inspections/save` flow.
- Inspections are stored in `inspections`; files are stored in `files`; PDFs are generated by `pdf.mjs`; existing regression coverage is in `tests/core.test.mjs` and related Node test files.
- The current room checklist expansion and default checklist behavior must be preserved exactly for existing routine inspections.

## Files to change

## Schema and migration

Create company/system templates, immutable template versions/items, property visit-type settings, and inspection snapshot metadata. Add nullable `template_id`, `template_version`, and `visit_type` to inspections; add nullable `answer_key` to files. Use forward-only ALTER/CREATE statements and preserve all existing rows and answers. Seed the existing 28-item routine checklist word-for-word plus room checks, then seed arrival, departure, pre-storm, post-storm, and monthly deep-check system templates. Existing routine resolution defaults to the system standard.

## API contracts

Implement company-scoped:
- GET/POST `checklist-templates`
- PUT `checklist-templates/:id/draft`
- POST publish/archive/set-default
- GET/PUT `properties/:id/checklist-settings`
- CSV import/export with row-level errors

Start inspection resolves explicit template, residence default, company default, then system default; snapshots expanded items. Save validates response values. Publish validates required answers, N/A notes, and photo rules and returns structured missing-item errors. All queries enforce company and role scope; system templates are read-only.

## UI and PDF

Add admin template list/editor/preview/import/export/archive/default controls with autosave, version changelog, keyboard reorder controls, and published-version warning. Add residence defaults/additions/hidden items. Extend start-inspection and inspection screens for visit type, response types, required labels, help toggles, per-item photos, and jump-to-unanswered. Keep help/internal notes out of client output. PDFs show template/version, render each response type, include item photos inline, and leave old reports unchanged.

## Permission matrix

- Admin: create/edit/publish/archive/import/export templates; set residence defaults/add/hide; choose templates; see help.
- Employee: choose templates and see help; may propose residence changes only through an existing note flow.
- Client/vendor: no template administration, selection, or help text.
- System templates: admin/employee read-only; duplicate before editing.
- Cross-company template access is denied.
